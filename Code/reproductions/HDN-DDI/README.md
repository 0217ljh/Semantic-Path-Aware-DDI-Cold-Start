# HDN-DDI Reproduction

Reproduce the cold-start results in Sun & Zheng (BMC Bioinformatics 2025),
Table 3, using:
- **Data**: jcsun-00/DrugBank repo (1706 drugs, 86 interaction types,
  191,808 positive instances), pre-split into 3 cold-start folds with
  fixed negatives.
- **Model**: our ported `coldddi.baselines.hdn_ddi.models.HDN_DDI` with
  `rel_total=86` (paper uses 86 distinct RESCAL relation embeddings).
- **Task**: per-triplet binary classification — predict whether
  `(d_x, r, d_y)` exists. Negatives are pre-generated by replacing
  either `d_x` or `d_y` with a random drug.

## Paper's reported numbers (Table 3, cold-start, mean across 3 folds)

| Partition | ACC | AUROC | AUPR | F1 |
|---|---|---|---|---|
| **Ds1** (new ↔ new, = paper's `s1.csv`) | 79.84 | 89.48 | 89.65 | 77.42 |
| **Ds2** (new ↔ old, = paper's `s2.csv`) | 89.43 | 95.92 | 95.95 | 89.34 |

## Data structure

```
_Original-Dataset/                      (cloned from jcsun-00/DrugBank; gitignored)
├── ddis.csv                            # 191808 positive (d1, d2, type) + neg drug
├── drug_smiles.csv                     # 1706 drugs → SMILES (drug roster)
├── cold_start/                         # cold-start train/val/s1/s2 splits
│   ├── fold0/{train,val,s1,s2}.csv     # paper fold 0
│   ├── fold1/...                       # paper fold 1
│   ├── fold2/...                       # paper fold 2
│   └── fold2015/...
├── warm_start/                         # warm-start splits
└── necessary/                          # model-required auxiliary files
    ├── id_data_dict__official.pkl          # official 3-level hierarchical mol graphs (40 MB)
    ├── id_data_dict__mine.pkl              # our builder's reproduction (sanity-check / fallback)
    └── build_hierarchical_pkl.py           # reproduction-side independent builder copy
```

The loader (`_pkl_loader.py`) **prefers `__official`** when present, falls
back to `__mine` when official missing, and **raises FileNotFoundError**
when both are missing (with a hint pointing at the manual builder CLI).
The reproduction pipeline does NOT auto-build (per CLAUDE.md §"复现代码
规范" step 6 — auto-build is baseline-side territory). One stderr line at
module-load time tells you which file fed this run.

## CSV format

Each row: `d1, d2, type, split, Neg samples`
- `d1, d2`: DrugBank IDs of the positive pair
- `type`: integer 0..85 (which of 86 interaction types)
- `split`: `<drug_id>$h` or `<drug_id>$t` — pre-generated negative drug
  to substitute the **h**ead or **t**ail position. Allows fully
  reproducible negatives.
- `Neg samples`: empty in cold-start CSVs.

## Reproduction protocol

For each fold (0, 1, 2):
1. Load `train.csv` → positives + paper-generated negatives (from `split` column, fixed)
2. Load `val.csv` → validation set (same format)
3. Load `s1.csv` (Ds1: new↔new) and `s2.csv` (Ds2: new↔old) → two cold-start test partitions
4. Build atom-level graphs for all drugs in `drug_smiles.csv`
5. Train HDN_DDI with `rel_total=86`, BCE on (pos, neg) pairs
6. Evaluate at each epoch on `val.csv` AUROC; keep best (paper-clean — no test-set peek).
   The upstream `inductive_train.py` selects on mean(s1+s2) which is a test-leak;
   we deviate intentionally for protocol cleanliness.
7. Report final ACC / AUROC / AUPR / F1 on s1 and s2 separately at the best-val checkpoint

Then average over 3 folds.

## Known fidelity caveats

These are differences between our port and the paper that may affect
reproduction numbers — **they do not affect the reproduction script** but
the underlying `coldddi.baselines.hdn_ddi` model implementation may
diverge here:

* **BRICS hierarchical decomposition**: paper uses a "refined BRICS"
  algorithm to decompose drugs into chemically meaningful substructures
  (paper §Substructure extraction module). Our `mol_features.py` ports
  the atom-level graph + a single molecular super-node (``y=2``) but
  does NOT implement BRICS substructure extraction. The
  hierarchical-view layer thus has only 2 hierarchy levels (atom +
  super-node) instead of 3 (atom + substructure + super-node). This
  could materially affect the cold-start numbers.
* **Validation selection**: we select on `val.csv` AUROC; upstream
  released code selects on mean of `s1+s2` metrics (test-set peek). Our
  protocol is cleaner; theirs may yield higher reported numbers.
* **Batch size**: paper text says 512, released code says 1024. We
  default to 512.

If reproduction numbers are off by >5%, the BRICS gap is the most likely
suspect.

## Hyperparameters

| Setting | Value | Source |
|---|---|---|
| `rel_total` | 86 | paper |
| `in_features` | 55 (ATOM_FEATURE_DIM) | paper |
| `hidd_dim` | 64 | paper §Parameters |
| `kge_dim` | 128 | paper §Parameters |
| `heads_out_feat_params` | (64,) × 6 | paper says 6 HDN Blocks |
| `blocks_params` | (2,) × 6 | 2 attention heads per GAT |
| `batch_size` | 512 (default) / 1024 | paper §Parameters says 512; `inductive_train.py` says 1024. We default 512 (paper-text); pass `--batch 1024` for code-fidelity |
| `learning_rate` | 1e-3 | paper |
| `weight_decay` | 5e-4 | paper |
| `n_epochs` | 100 (early-stop patience 30) | paper |
| scheduler | LambdaLR with 0.96 decay | paper |

## How to run

```bash
# fold 0 only (smoke verify)
python Code/reproductions/HDN-DDI/run_faithful.py --fold 0 --tag fold0_faithful

# all 3 folds (full reproduction); wrapper auto-runs fold 0/1/2 with the
# default per-fold tag `fold{N}_faithful` and aggregates results:
python Code/reproductions/HDN-DDI/run_3fold.py

# wrapper accepts `--folds N [N ...]` and `--out <path>`; any args for
# run_faithful.py must come after `--`, e.g. to pass `--n_workers 4`:
#   python Code/reproductions/HDN-DDI/run_3fold.py -- --n_workers 4
# (do NOT forward --tag; run_3fold's run-dir discovery requires the
# default `fold{N}_faithful` tag)
```

Results saved to `Code/runs/<timestamp>__hdn_ddi_faithful__fold{N}_faithful__seed{S}/results.json`.

- `model.py:380-384` defines the dual-channel forward path (mol GT +
  BKG GT → concat → fc1 → fc2)

- Matches reproduction `model/tiger.py` semantics

### C2 — relation-aware self-attention ✅

  spatial bias add → einsum scoring
- Same convention as reproduction `model/graph_transformer.py:235-263`
  (including the `q[col]/k[row]` vs paper's `q[row]/k[col]` quirk —
  preserved from upstream for bit-faithfulness)

### C3 — three subgraph extractors ❌

- `subgraph_features.py:1-3` docstring: "Ports the `rwExtractor` branch
  ... random-walk extractor"
- Only **DeepWalk / random-walk** extractor is wired
- **Missing**: `khop-subtree`, `probability` (paper has both —
  `_paper_text.txt:565-570` Table 2 reports TIGER-KS / TIGER-DW / TIGER-P
  as separate rows with their own numbers)

- Per CLAUDE.md §6 line 617: "拍脑袋'为了简化省略 paper 的 X 步骤'"
  (paper 算法细节不允许私自简化)
- **VERDICT**: C3 is a paper-algorithm-omission violation. Must fix.

### C4 — MI auxiliary loss ✅

- Dual-channel path (`model.py:387-399`): both `loss_s_m` (mol-atom MI)
  and `loss_s_d` (sub-node MI) computed; `loss = label + β1·s_m + β2·s_d`
- mol-only path (`model.py:338-343`): only `loss_s_m` (correct, no
  sub-node available without BKG)
- Matches reproduction semantics

## 5. Anti-pattern audit (CLAUDE.md §4 line 580-584, §6 line 615)

CLAUDE.md calls out the canonical anti-pattern:
> 没用 builder, 在 `baseline/hdn_ddi/mol_features.py` 写 "independent
> re-implementation", 每次 fit() on-the-fly BRICS 分解

### TIGER incidence: 2 instances of the same anti-pattern

1. **`mol_features.py:84 mol_to_data()` + `:136 build_drug_graphs()`**
   - Re-implementation of reproduction's `data_process.py:single_smile_to_graph`
   - No `__mine` artefact, no detect-and-build, no `_data/necessary/`
   - Every `fit()` rebuilds mol graphs from SMILES on the fly
   - **Direct equivalent of pre-fix HDN bug**

2. **`subgraph_features.py` rwExtractor port**
   - Port of reproduction's `data_process.py:rwExtractor` only (not all 3)
   - Same on-the-fly pattern: every fit() runs DeepWalk for every drug
   - No cache, no `_data/necessary/<...>__mine.json`

### What's NOT anti-pattern

- `kg_builder.py` builds BKG from merged parquet — this is a legitimate
  baseline-side extension (paper uses upstream `networks.txt`, we use
  merged KG, so a separate builder is the right architecture)
- `model.py:_patch_unseen_center_nodes` is a non-paper cold-start
  adaptation, documented explicitly. Project extension category, not
  anti-pattern (see §7 for caveat).

## 7. Three-bucket discrepancy classification

### paper-vs-impl (paper text vs baseline code)
- ❌ **algorithm-omission**: only 1 of 3 extractors (random-walk only;
  missing k-subtree + probability). Paper Table 2 reports TIGER-KS,
  TIGER-DW, TIGER-P as 3 distinct methods.
- ⚪ Cold-start `_patch_unseen_center_nodes` adds non-paper logic to the
  default forward path. Default `tiger` registration runs paper +
  extension when `g2_idx` is non-empty.

### repo-vs-impl (upstream code vs baseline port)
- ⚪ `mol_features.py` is independent re-implementation, not a literal
  port of upstream `data_process.py:single_smile_to_graph` —
  algorithmically equivalent but separately maintained
- ⚪ `subgraph_features.py` is independent port of upstream `rwExtractor`
  only
- ⚪ `kg_builder.py` replaces upstream `networks.txt` reading with merged
  parquet ingestion — necessary deviation for our data

### baseline-vs-spec (CLAUDE.md §"Baseline 规范" violations)
- ❌ Flat layout (no `binary_cls/`, `multi_cls/`)
- ❌ Filename-suffix anti-pattern (`baseline_multiclass.py`)
- ❌ Missing `_results/`, `_reviews/`, `_data/`, `_data/necessary/`
- ❌ Missing `_data/necessary/build_*.py` (copied from reproduction)
- ❌ Missing `_shared.py` detect-and-build pipeline
- ❌ Anti-pattern: in-baseline re-implementation of preprocessing logic
  instead of `_data/necessary/__mine` consumer pattern

## 8. Final verdict: ❌ FAIL

The TIGER baseline is **functionally usable** (codex confirms C1+C2+C4
algorithms work) and **scientifically interesting** (cold-start patch
is a useful extension), but it fails CLAUDE.md §"Baseline 规范" on
multiple fronts:

| Category | Status |
|---|---|
| Paper-algorithm preservation | ❌ C3 omission (2/3 extractors missing) |
| Layout conformance | ❌ 7 deviations |
| Anti-pattern check | ❌ 2 instances (mol_features + subgraph_features) |
| Detect-and-build pipeline | ❌ missing entirely |
| Cross-folder independence | ✅ verified clean |

Cannot be marked PASS without (at minimum) the 5 prioritised fixes from
codex §6.

# Insight 3

> **图上的 attention 是数据内部的加权，不能注入外部语义先验；DDI 的关键 mediator 需要外部先验才能被感知。**

---

## 支撑实验

### 数据集

- 合并 KG：DrugBank + Hetionet + PrimeKG，178,029 节点 / 7,099,528 边
- ColdDDI seed=42，S2 split
- LLM oracle：Sonnet 4.5 / Opus 4.6 + GPT-4o，n=30-60 per class
- 路径类型人工标签：219 path-type，1/2/3 评分（来自之前 exp1-0512）

### 四条腿的证据

**1. 直接证据（E3 init comparison）**：当 attention 内部加权无法获取的信号，由外部语义先验注入后被解锁。

| Init | Random Proj | PCA Proj |
|---|---|---|
| Random Gaussian | 0.639 | — |
| Type one-hot（无外部语义）| 0.686 | — |
| **Real PubMedBERT [CLS]** | 0.654 | **0.708** |
| Shuffled-name PubMedBERT（语义被打散）| 0.614 | 0.654 |
| Type-name only（仅类别名语义）| 0.642 | 0.672 |

Paired ΔAUROC (PCA proj)：
- Real − Shuffled: **+5.65pt** [CI +5.30, +6.00]，CI 排除 0
- Real − Type-name: +3.47pt
- Real − Type-onehot: +2.64pt

**含义**：在同一架构、同一容量、同一投影下，**只有 real node-name semantics** 让 AUROC 拉到 0.708；topological-only / type-only 都只到 0.65-0.69。这一信号**不在拓扑结构里**，必须由 text-encoder 从外部注入。

**2. Noise dilution claim 收紧（E6 simplified · pool-size ablation）**：

| k (top-k features) | Test S2 AUROC |
|---|---|
| 1 (1hop_protein_gene only) | 0.685 |
| 3 | 0.705 |
| 5 | 0.703 |
| 8 | 0.711 |
| 12 | 0.717 |
| 16 | **0.717** |
| 22 (all) | 0.717 |

**LR + L2 正则化下没有 noise dilution**——加更多噪声特征不掉性能。所以原 i3 表述里的"uniform pool drowns signal"半边在简单线性模型上**不成立**。

**收紧后的 i3 主张**：i3 的核心不是 "pool 把信号淹没"，而是 **"attention 这套数据内部加权机制存在 perception block——它能在已有特征上做权重分配，但不能引入新的语义信息"**。

**3. 间接证据（E8.2 → E8.6 LLM oracle 升级）**：

| 设计 | PD-effect AUROC | PK-effect AUROC |
|---|---|---|
| Single-stage bag + name (E8.2，effectively 内部 attention) | 0.652 | 0.510 |
| **Pair-conditional selection + name (E8.6)** | **0.739** | 0.619 |
| Δ | **+8.7pt** | +10.9pt |

bag prompt 给 LLM 全部 20 个 effect 让它"自己挑"——这等价于让 LLM 做内部 attention。PD-effect 只有 0.652。把"selection"显式分离成 stage（先选关键 pair 再 score），AUROC 直接 +8.7pt。

**含义**：即便对一个比 GNN attention 强得多的 LLM，**bag-with-internal-attention 仍不够**；必须把 selection 显式化、pair-conditional 化。这正是 "attention can't inject external priors" 的实证。

**4. 文献支撑（c3 cold-start 综述）**：DDI-Ben (2024) 表明：纯 KG/GNN/attention 方法在 distribution shift 下性能崩溃，text/LLM 方法稳定得多。TextDDI、ZeroDDI 用文本先验的方法显著优于纯 topology。

## "Attention 不足" 的精确诊断

| 类型 | 操作 | i3 的判断 |
|---|---|---|
| **数据内部 attention** | 给已有的邻居特征学习权重 | 受 perception block 限制；只能在 KG 拓扑给定的特征空间内重排，不能引入新维度 |
| **External semantic prior** | 用 pretrained encoder 把节点名编码成 vector 注入 init | E3 直接证明 +5.65pt；这一信号**不能从拓扑学出来** |
| **Pair-conditional selection** | 跨两 drug 看相关 candidate 节点，挑出 compositional 配对 | E8.6 +8.7pt 实证；attention 加 selection 等价于 attention + 外部 query 条件 |

i3 不是说"attention 没用"，是说 **"attention 单独不够；它在 cold-start 低 SNR 环境下感知不到关键节点，必须配合外部语义先验和显式 selection"**。

---

## 与 i2、i4 的关系

i2 / i3 / i4 是闭环：

- **i2** 说：DDI 信号在 meeting node 处汇聚（不是 drug 端点）
- **i3** 说：要识别 meeting node 中真正重要的那些，attention 内部加权不够，需要外部 prior
- **i4** 说：外部 prior 的最佳形式是 node-name 文本语义（cold-start 稳定）

i3 是"perception 必要性"的桥梁——它说明 i2 给的 anchor location 不够，**还要 i4 提供的语义信号** 才能 selection 起来。

## 对论文方法的启示

- Backbone：浅 GCN K=2（per i2）
- Init：PubMedBERT([node.name]) 投影（per i4）
- Readout：在 M 上做 **pair-conditional, per-instance attention**（不是 uniform 池化，不是 relation-type 共享 attention）
- 监督：标准 DDI pair label 即可——i3 的关键不是改 supervision，是改架构感知方式

**与现有方法的差距**：
- GAT / GraphSAGE-style attention：相同关系类型 / 相同跳数的邻居共享同一组 attention params → block
- EmerGNN relation-type attention：α_r per relation type，pair-conditional 但不区分同 type 实例 → block
- 我们的 per-instance pair-conditional attention with PubMedBERT prior：unblock

---

## Caveats

- E6 simplified 表明 i3 的"pool drowns"半边在 LR 上不成立——i3 的精确表述是 "attention 不能注入外部 prior"，**不是** "pool 总是把信号淹没"
- 节点名 text 语义是 plausible / high-yield 的外部先验来源，但**不是唯一**——其它语义来源（分子结构 SMILES embedding、phenotype ontology embedding 等）原则上也能起作用，这部分留作 future work
- i3 的 perception block 论断在 GNN 上是 architectural conjecture，需要 i3 专门的 attention ceiling 实验来更严格地证明（如 saturate GAT 各种 head 数都不能匹配 PubMedBERT init 的效果）

# Insight 2

> **DDI 预测的表征锚点应是 drug pair 的 meeting node（共同中介），而不是 drug 节点本身；强制把信号从一个 drug 流到另一个 drug 需要 GNN 层数与路径等长，必然落入 over-smoothing。**

---

## 支撑实验

### 数据集

- 合并 KG：DrugBank + Hetionet + PrimeKG，178,029 节点 / 7,099,528 边
- ColdDDI seed=42，S2 split（G2 drugs，cold-start 未见过）

### 四条腿的证据

**1. 距离层（E1a · SSPL 分布）**：多数 pair 2-hop 可达，但 **20% 必须深度 ≥ 3**，恰好落入 over-smoothing 风险区。

| Split | 中位 SSPL | ≥3 hop 占比 |
|---|---|---|
| Train | 2 | 19.5% |
| Test S2 | 2 | **20.8%** |

**2. 行为层（E2 · depth-vs-AUC + collapse 诊断）**：vanilla GCN 深度 ≥ 4 时 AUC 单调下降 + embedding collapse。

| K | Vanilla AUC | Cosine sim | Dirichlet energy |
|---|---|---|---|
| 1 | 0.627 | 0.24 | 700 |
| **2** | **0.680** | 0.17 | 86 |
| 4 | 0.658 | 0.03 | **19** |
| 6 | 0.648 | 0.02 | 16 |
| 8 | 0.641 | 0.08 | 20 |

AUC K=2→8 单调降 **−3.86pt**；Dirichlet K=2→4 急降 86→19；K=8 单 seed dim_var=0.003（经典 collapse）。

**Controls**：
- PairNorm rescue: K=2→8 衰减只剩 **−1.49pt** (vs vanilla −3.86pt) → ~60% 的深度衰减由 over-smoothing 解释
- MLP-control (无 message passing): K=2 / K=8 AUC=0.50 (chance) → message passing 必需，drug 之间需要 KG 邻域传 signal

**3. 架构对照层（E7 · meeting-node LR baseline）**：22 维手工 shared-mediator 特征 LR 超过 vanilla GCN。

| Model | Test S2 AUROC |
|---|---|
| LR over 22 shared-mediator features (count, log1p) | **0.7171** [0.7140, 0.7198] |
| Vanilla GCN K=2 (E2) | 0.680 |
| 差距 | **+3.7pt（meeting-node LR 胜）**  |

最重要的特征系数（LR-count）：`1hop_protein_gene` (+1.02), `1hop_compound` (+0.50), `2hop_pathway` (−0.33)。

含义：**meeting node 处的简单共享统计已经 carry most of the DDI signal**——drug-anchored 深度 GCN 把这部分信号在多层聚合中稀释了。

**4. 文献理论层（c8 over-smoothing cluster）**：

| 论文 | 贡献 |
|---|---|
| Oono & Suzuki (ICLR'20) | GNN expressive power **指数衰减** with depth |
| Li et al. (AAAI'18) | Over-smoothing 来自 Laplacian smoothing |
| Xu et al. (ICML'18) JKNet | Jumping skip connections mitigation |
| Rong et al. (ICLR'20) DropEdge | Random edge dropping |
| Chen et al. (ICML'20) GCNII | Initial residual + identity mapping |
| Zhao & Akoglu (ICLR'20) PairNorm | Pairwise distance normalization |
| Alon & Yahav (ICLR'21) | Over-squashing 作为对偶问题 |
| Topping et al. (ICLR'22) | Curvature characterization of over-squashing |

**c8 cluster 总结**：这些论文都在 Cora / Citeseer / OGB 上做 over-smoothing 诊断，没有任何一篇专门在 **DDI / KG-增强 DDI 语境**下做这件事。E2 是首次在 DDI 上系统诊断 over-smoothing 的实证研究，cited 上面理论作支撑。

## 与 EmerGNN 的对比（重点）

EmerGNN (Zhang et al., Nat. Comp. Sci. 2023) 是 cold-start DDI 上最直接的 path-flow 路线、也是我们的 #1 must-compare baseline。两条路线表面相近——都不走 drug-embedding-only 的范式，都关注 pair 间的 path——但**底层归纳偏置不同**，边界值得拆清楚。

### EmerGNN 的核心机制

1. 对一对 query drug (u, v)，在合并 KG 上抽取所有长度 ≤ L 的路径，union 成 path-subgraph
2. **Bellman-Ford 风格的 flow-GNN**：representation 从 u **流向** v，每条边带 relation-conditioned 的学习权重
3. Pair 表征 = u 出发流到 v 时在 v 上累积的 embedding
4. Edge weights 充当 attention 同时做 path 解释

### 我们的核心机制

1. 对一对 query drug (u, v)，找它们 1-hop / 2-hop 邻域的交集——即 **meeting nodes** $M = N(u) \cap N(v)$
2. 表征锚定在 meeting node 上：对 M 中节点的 GCN embedding 做 pair-conditional 聚合（含 PK/PD 类型先验、节点名 text 语义先验）
3. Pair score = $f(\text{emb}_M, \text{emb}_u, \text{emb}_v)$ 中 emb_M 占主导
4. 选择哪些 M 节点入 readout 由 i3/i4 的 pair-conditional perception 决定

### 五点边界差异

| 维度 | EmerGNN (flow) | Ours (meeting node) |
|---|---|---|
| **锚点位置** | 终点 drug v（信号流到的目标） | **中间 meeting node M**（信号汇聚的交点） |
| **路径遍历方向** | 单向 u → v（Bellman-Ford 有方向性） | 双向收敛 u ↘ M ↙ v（对 u, v 对称） |
| **深度 = 路径长度？** | 是。L=4 路径就要 4 步 flow → 长路径下 over-smoothing 风险存在 | 否。我们只读到 M（M 一般在 1-hop / 2-hop），不需要"从 u 走到 v"的 full traversal |
| **类型先验** | Relation-conditioned edge weights（学出来）；没有显式 PK / PD 区分 | M 的 kind 显式区分（molecular vs effect）→ 直接对应 i1 的 PK / PD 范式 |
| **节点语义** | 中间节点用 ID-embedding（learned）| 节点名 text 语义（PubMedBERT）作为 init 先验（i4）|

### 为什么这个边界很重要

**EmerGNN 解决的是**：cold-start drug 之间没有训练时连接，怎么通过 KG path 把它们关联起来——**flow 是手段，drug v 是目的地**。

**我们解决的是**：cold-start drug pair 的 DDI signal 究竟存在于哪里——**meeting node 是 signal 载体，flow 只是 dataflow 实现**。

两条路线对 SSPL 分布的处理也不同：
- EmerGNN 对 SSPL ≥ 3 的 pair（E1a 测出来的 20%）通过提高 L 来覆盖；代价是 path 长度上的 over-smoothing
- Ours 对同样这 20% pair，可以让 meeting node 在 2-hop 或 3-hop 交集层，但**不需要 "u 走到 v" 的 full path traversal**——meeting-node readout 是 local 的，不积累 path-length 的 over-smoothing

### 何时 EmerGNN 比我们好

- Pair 之间**没有明显单一共同中介**，信号靠多跳因果链（drug A → enzyme X → pathway Y → effect Z → drug B）累积——EmerGNN 的 flow 抓得到，我们的 meeting node 集合可能为空或过于稀疏
- **Path 级别的可解释性**是论文目标（"哪条 path 最重要"）——EmerGNN 的 edge weights 直接给出

### 何时我们比 EmerGNN 好

- Pair **有明显共享 mediator**（典型 PK-A：共享 enzyme；典型 PD-B：共享 SE）——meeting node 直接 capture，flow 反而要 traversal
- 信号在 PK / PD 范式上有差异——我们的 meeting-node 类型先验直接对应 i1
- 需要 cold-start 下利用节点名 text 语义先验（i4）——meeting node 是 individually 可读 PubMedBERT-encoded 的 entity，flow 路径上中间 ID-embedding 节点没有这个先验
- SSPL 大头 2-hop 的 80% pair（E1a）——meeting node 直接读 1-hop 交集，无需 path traversal
- 想避免 path-length 上 over-smoothing 这条结构性缺陷

### 两条路线能不能 compose？

可以——meeting node 视为"路径上的强信号枢纽"，在 meeting node 之外的 path 段仍可用 EmerGNN 式 flow。但 paper 边界应当先定主：**我们的主张是 meeting-node-anchored**（i2 + i3 + i4 闭环），flow 是 fallback 工具，不是主结构。

## 与其他相关路径方法的对比（次要）

| 方法 | 主结构 | 与我们的核心差异 |
|---|---|---|
| **SumGNN** (Yu 2021) | Pair-subgraph + self-attention pooling | 子图是 drug-drug 局部子图，不显式提取 meeting node；attention 在数据内部加权，无外部 prior |
| **KnowDDI** (Wang 2024) | KG subgraph + 学习连接强度 | 类似 SumGNN，subgraph 加强但仍 drug-anchored；明确不用 text 先验 |
| **BioPathNet** (Hu 2024) | NBFNet 的 pair-conditional path rep | 最接近"非 drug-anchored"精神，但 readout 仍在终点 drug；不区分 PK / PD |
| **K-Paths** (Abdullahi 2025) | RL path 检索 | path-level 选择，靠 RL 而非 semantic prior；与 EmerGNN 同类 |
| **HyGNN, MPHGCL-DDI** | Hypergraph / meta-path 平均 | 对所有路径类型一视同仁，与 i1 / i3 抵触 |

**结论**：5 个 path-based 方法都属于 "path-on-drug-endpoint" 范式（drug-anchored readout）；**我们的 meeting-node-anchored 范式没有现成对手**。

## 对论文方法的启示

- Backbone 可以是 GCN / GAT / R-GCN 任何浅 GNN（K=2 足够，per E2）
- Decoder **不**用 drug-pair dot product；改成 meeting-node readout：
  1. 找 $M = (\text{N}_1(u) \cup \text{N}_2(u)) \cap (\text{N}_1(v) \cup \text{N}_2(v))$（1-hop ∪ 2-hop 交集）
  2. 用 pair-conditional attention 在 M 上加权（i3 的"语义 perception"）
  3. M 中节点的 init embedding 来自 PubMedBERT([node.name]) 投影（i4）
  4. 类型先验：molecular-kind M 走 PK 通道，effect-kind M 走 PD 通道（i1）
- 不需要走 EmerGNN 风格的 path traversal；浅 GCN 给 M 中节点准备好局部 representation 即可

---

## Caveats

- E7 是手工 LR baseline，**不是 learnable meeting-node anchor**；i2 还缺一个干净的 GNN-decoder 架构对照（drug-anchored vs meeting-node-anchored，同 backbone），可补 E9
- 跨数据集复现：当前只在 ColdDDI seed=42 上测；多种子 / DDI-Ben split 复现可加强
- 与 EmerGNN 的直接 head-to-head：方法实现后在他们公开的 S1 / S2 split 上对比
- "20% pair 需 ≥ 3 hop" 是 SSPL 角度的论证，不能直接等同于"必须 GCN ≥ 3 层"——shallow GCN + meeting-node readout 也可以覆盖这部分
